# ELAN Fingerprint на ASUS Zenbook UM431DA (Arch Linux, KDE Plasma)

## 1. Результаты исследования

| Вопрос | Результат |
|---|---|
| VID | `04f3` (Elan Microelectronics Corp.) |
| PID UM431DA | В открытых источниках (libfprint issues, форумы, Launchpad) PID именно для UM431DA не опубликован. Определяется на устройстве: `scripts/detect.sh` |
| Поддержка libfprint (upstream v1.94.100, commit `6f9479c3`) | 61 PID в драйвере `elan`, 17 PID в `elanmoc`, SPI-вариант `elanspi`; 35 PID ELAN явно помечены неподдерживаемыми (в `detect.sh` исключен `3057`: это HID-тачпад, используемый драйвером `elanspi`) |
| Протокол | Задокументирован: `docs/protocol.md` |
| Windows-драйвер | ELAN WBF-драйвер с сайта ASUS; используется только как источник USB-трафика (`docs/reverse-engineering.md`) |

Варианты по итогам `detect.sh`:

- **A. PID в таблице `elan`/`elanmoc`** — собственная реализация не требуется. Пункт 2.
- **B. PID в списке неподдерживаемых или неизвестен** — пункт 3.

## 2. Установка (вариант A)

```sh
./scripts/detect.sh
sudo ./scripts/install-arch.sh
fprintd-enroll                       # регистрация
./tests/enroll-verify.sh "$USER" 10  # тесты на реальном сенсоре
```

Альтернатива для регистрации в GUI: «Параметры системы → Пользователи → Настроить вход по отпечатку» (Plasma 6).

## 3. Собственная реализация (вариант B)

1. Проверка, совместим ли сенсор с протоколом драйвера `elan` (самый частый случай):
   ```sh
   ./tests/run-emulated.sh <pid>       # сборка + эмулированные тесты, без оборудования
   cd driver && ELAN_PID=<pid> makepkg -si
   ```
2. Если протокол не совпадает — захват и анализ трафика Windows-драйвера, новый драйвер: `docs/reverse-engineering.md`.

Состав `driver/`:

| Файл | Назначение |
|---|---|
| `add-elan-pid.sh` | добавляет PID в `elan_id_table`, удаляет из списка неподдерживаемых |
| `make-mock-variant.sh` | создает umockdev-тест `tests/elan-<pid>` из эталонной записи `tests/elan` |
| `PKGBUILD` | пакет `libfprint-elan-extra-pid` (заменяет `libfprint`), `check()` запускает тесты |

## 4. Тесты

| Тест | Оборудование | Что проверяет |
|---|---|---|
| `tests/run-emulated.sh <pid>` | нет | upstream-тесты `elan`, `elan-cobo`, `elanmoc`; привязку драйвера к новому PID (позитивный контроль); отсутствие привязки без патча (негативный контроль) |
| `tests/enroll-verify.sh` | да | видимость сенсора, регистрацию, FRR (тот же палец), FAR (другой палец), сохранность после перезапуска fprintd, PAM через `pamtester` |

Результат `run-emulated.sh 0c4c` в среде разработки (Ubuntu 24.04, libfprint v1.94.100):
```
upstream тесты драйверов: Ok 3, Fail 0
позитивный контроль: PASS
негативный контроль: PASS (драйвер не привязан, как ожидалось)
```
PID `0c4c` использован как пример неподдерживаемого upstream ELAN PID. Эмуляция подтверждает привязку драйвера и обработку записанного трафика, но не совместимость протокола конкретного сенсора — это проверяется только на оборудовании.

## 5. PAM и KDE Plasma

```sh
sudo -i                              # резервный root-терминал, оставить открытым
sudo ./pam/apply-pam.sh              # sudo + polkit-1 (диалоги KDE)
sudo ./pam/fprintd-hardening.sh      # регистрация отпечатков только с паролем администратора
sudo ./pam/apply-pam.sh --revert     # откат
```

| Сервис | Действие | Обоснование |
|---|---|---|
| `kde-fingerprint` (экран блокировки) | без изменений | Plasma 6 `kscreenlocker` уже содержит отдельный PAM-сервис для отпечатка; пароль работает параллельно |
| `sudo` | `auth sufficient pam_fprintd.so` | пароль остается запасным путем; `pam_fprintd` пропускает удаленные сеансы (SSH) |
| `polkit-1` | `auth sufficient pam_fprintd.so` | подтверждение действий в KDE |
| `sddm` (вход) | не изменяется | при входе по отпечатку KWallet не получает пароль и не разблокируется. Необязательный шаблон: `pam/sddm.optional` |
| `system-auth` | не изменяется | изменение затрагивает все сервисы, включая `su`, `passwd` |

Параметры `max-tries=3 timeout=15` ограничивают число попыток и время ожидания, после чего управление переходит к паролю.

## 6. Ограничения

- Реальный сенсор в среде разработки отсутствует. Скрипты для оборудования (`detect.sh`, `install-arch.sh`, `enroll-verify.sh`, `apply-pam.sh`, `capture-usb.sh`) проверены синтаксически и на имитации sysfs, но не на UM431DA.
- Шаблоны драйвера `elan` хранятся на хосте (`/var/lib/fprint`), не в защищенном хранилище сенсора. Отпечаток — удобство, а не замена пароля для защиты от физического доступа.
